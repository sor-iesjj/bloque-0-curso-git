## EJ-01-02-05 — Marko clona el repo de Carlos para consultarlo

> [!info] Situación
> Carlos ha publicado un repo `scripts-utiles` con scripts de mantenimiento. Marko quiere tenerlo en local para consultarlo y aprender.

- **🎯 Objetivo real:** aprender `git clone` para descargar repositorios ajenos completos (con su histórico), y ver que funciona con **las dos formas de autenticación**.
- **🧩 Problema que resuelve:** sin clonar, Marko solo puede ver el código en el navegador (incómodo). Clonado, lo abre en su editor.

---

## 📚 Fundamento

> [!info] Antes de empezar: clonar es "bajar una copia completa"
> `git clone` descarga **todo** un repositorio: sus archivos **y su historial**. No es como bajar un ZIP: te traes también todos los commits, para poder consultarlos con `git log`. Además, al clonar, Git ya deja configurada la conexión (`origin`) con el repo original.

> [!abstract] Idea clave: un repo, dos puertas
> El profesor te dará **un** enlace del repositorio. Con ese mismo repo puedes entrar por **SSH** (`git@github.com:...`) o por **HTTPS** (`https://github.com/...`): es la misma casa por dos puertas. Usa la vía que montaste al preparar el entorno.

> [!example] Vocabulario de esta práctica
> - **`git clone`:** descarga por primera vez un repositorio a tu ordenador.
> - **`origin`:** el nombre que Git le da al repositorio remoto de origen.
> - **Permiso de lectura:** puedes ver y clonar, pero no subir cambios (`push`) al repo de otro.

## 🛠️ Procedimiento

> [!example] Paso 1 — Sitúate en tu bóveda (NO dentro de un repo)
> Clona en el contenedor `Boveda_Marko/`, no dentro de `Manuales/`.
>
> *🐧 Git Bash / Linux*
> ```bash
> cd ~/Boveda_Marko
> ```
> *🪟 PowerShell*
> ```powershell
> cd $env:USERPROFILE\Boveda_Marko
> ```

> [!example] Paso 2 — Clona el repositorio (elige tu vía)
> Las dos bajan **el mismo** repo:
>
> *🔑 SSH*
> ```bash
> git clone git@github.com:carlos-boochan/scripts-utiles.git
> ```
> *🔐 HTTPS*
> ```bash
> git clone https://github.com/carlos-boochan/scripts-utiles.git
> ```
> *Nota: Carlos es ficticio. En clase, el profesor te da una URL real (por ejemplo, un repo suyo con ejemplos).*

> [!example] Paso 3 — Entra y explora
> ```
> cd scripts-utiles
> ls
> git log --oneline
> ```

> [!example] Paso 4 — Mira de dónde viene (el remoto)
> ```
> git remote -v
> ```
> Verás `origin` apuntando al repo de Carlos.

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Clonas dentro de `Manuales/` | Tendrías un repo dentro de otro | Comprueba con `pwd` que estás en `Boveda_Marko/` antes de clonar. |
> | `Permission denied (publickey)` | Usas SSH pero la clave no está lista | Clona por HTTPS, o repasa tu clave SSH. |
> | Intentas `git push` al repo de Carlos | Falla: no tienes permiso de escritura | Sobre repos ajenos solo tienes lectura. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - La carpeta `scripts-utiles/` existe dentro de `Boveda_Marko/` y tiene contenido.
> - `git log --oneline` muestra los commits de Carlos.
