## EJ-01-02-04 — Marko navega su histórico (`git log`)

> [!info] Situación
> Lucía le pregunta a Marko en una reunión: *"¿Cuándo añadiste lo del NSG al manual?"* Marko no se acuerda. Quiere consultar su histórico.

- **🎯 Objetivo real:** dominar `git log` y sus variantes: ver qué se ha hecho, cuándo, por quién, y filtrar por contenido.
- **🧩 Problema que resuelve:** sin saber consultar el histórico, Marko no puede responder preguntas básicas sobre su trabajo y pierde tiempo investigando lo que ya hizo.

---

## 📚 Fundamento

> [!info] Antes de empezar: el histórico es la memoria del proyecto
> Cada commit que has hecho queda guardado con su **hash** (identificador único), su **autor**, su **fecha** y su **mensaje**. `git log` es la herramienta para **navegar** por esa memoria: es como pasar las páginas del cuaderno de bitácora del proyecto.

> [!abstract] Idea clave: por eso importan los buenos mensajes
> Aquí se ve la recompensa de escribir mensajes de commit claros: si son buenos, `git log` te responde en segundos "¿cuándo hice X?". Si son basura ("cosas", "cambios"), el histórico no sirve de nada.

> [!example] Vocabulario de esta práctica
> - **Hash:** identificador único de cada commit (una ristra de letras y números).
> - **`--oneline`:** muestra cada commit en una sola línea (resumen).
> - **`--grep`:** filtra commits buscando texto **en el mensaje**.

---

## 🛠️ Procedimiento
Trabaja dentro de `Manuales/`.

> [!example] Paso 1 — Histórico completo
> ```
> git log
> ```
> Muestra hash, autor, fecha y mensaje de cada commit. **Se sale pulsando `q`.**

> [!example] Paso 2 — Histórico compacto (el más usado)
> ```
> git log --oneline
> ```

> [!example] Paso 3 — Histórico con los cambios de cada commit
> ```
> git log -p
> ```

> [!example] Paso 4 — Histórico en forma de grafo
> ```
> git log --oneline --graph --all
> ```

> [!example] Paso 5 — Buscar por el mensaje (responder a Lucía)
> ```
> git log --grep="NSG"
> ```

> [!example] Paso 6 — Ver qué commits tocaron un archivo
> ```
> git log -- 01_linux_server/instalacion_ubuntu.md
> ```

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Te quedas "atrapado" en `git log` | La pantalla no responde | Es normal: pulsa **`q`** para salir. |
> | Buscas código con `--grep` y no aparece | `--grep` busca en **mensajes**, no en el código | Para buscar en el código se usa `git log -S`. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - Sabes responder de viva voz: *"El NSG lo añadí en el commit EJ-01-02-01"*.
> - Tu bitácora tiene la entrada de esta práctica.

> [!question] Comprueba que lo has entendido
> Responde en tu bitácora:
> 1. ¿Qué información muestra `git log` de cada commit?
> 2. ¿Cómo se sale de la vista larga de `git log`?
> 3. ¿Qué hace `--grep` y sobre qué busca?
