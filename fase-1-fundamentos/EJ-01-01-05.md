## EJ-01-01-05 — Marko publica su repositorio de manuales en GitHub

> [!info] Situación
> Lucía pasa por la mesa de Marko: *"Muy bien, ya tienes el manual guardado en tu ordenador. Pero si se te rompe el portátil, se pierde. Súbelo a GitHub para que quede a salvo y para que Carlos y yo podamos verlo."* Marko crea su cuenta, conecta su repositorio local con uno remoto y lo publica. Como es la primera vez, elige **cómo va a autenticarse**.

- **🎯 Objetivo real:** crear un repositorio remoto y enlazar el local con `git remote add` + `git push -u`, aprendiendo **las dos formas de autenticar**: SSH y HTTPS + token.
- **🧩 Problema que resuelve:** si el portátil se rompe, el trabajo se pierde. GitHub es el backup y el punto donde el equipo consulta la documentación.

---

## 📚 Fundamento

> [!info] Antes de empezar: local y remoto
> Hasta ahora tu repositorio `Manuales/` vivía **solo en tu ordenador**. Publicar es conectar ese repo local con un **repositorio remoto** en GitHub (llamado `origin`) y **subir** tus commits con `push`. A partir de ahí, GitHub es la "copia maestra" accesible desde cualquier sitio.

> [!warning] Publicamos el REPOSITORIO, no la bóveda
> Subes `Manuales/` (que se llamará `manuales-boochan` en GitHub), **no** `Boveda_Marko/`. La bóveda contenedor nunca se sube entera.

> [!abstract] Idea clave: un repo, dos formas de autenticar
> Para que GitHub sepa que eres tú, necesitas identificarte. Hay **dos vías** (elige una; puedes probar las dos):
> - 🔑 **SSH** (recomendada): se configura una vez con una clave, no pide contraseña, no caduca.
> - 🔐 **HTTPS + token**: usas un *Personal Access Token* como contraseña; más simple, pero caduca.

> [!example] Vocabulario de esta práctica
> - **Remoto / `origin`:** el repositorio en GitHub al que se conecta tu repo local.
> - **`git remote add`:** enlaza local ↔ remoto.
> - **`git push -u origin main`:** sube y deja enlazada la rama.
> - **Token (PAT):** contraseña temporal para la vía HTTPS.

---

## 🛠️ Procedimiento

> [!example] Paso 1 — Crea la cuenta y el repositorio remoto (común a las dos vías)
> 1. En `https://github.com`, crea tu cuenta si no la tienes (usuario tipo `marko-boochan`).
> 2. Pulsa **"+" → "New repository"**.
> 3. Configura: **Repository name** `manuales-boochan`; **Visibility** **Private** (das acceso a Lucía y Carlos como colaboradores); **NO** marques "Add a README" (ya existe local).
> 4. Crea el repo. En el botón **`Code`** verás las dos direcciones (`SSH` y `HTTPS`).

> [!example] Paso 2 (🔑 vía SSH, recomendada) — Configura la clave y sube
> Si no tienes clave todavía:
> ```bash
> ssh-keygen -t ed25519 -C "tu-correo"
> cat ~/.ssh/id_ed25519.pub
> ```
> Pega la clave **pública** en GitHub (**Settings → SSH and GPG keys → New SSH key**). Luego, dentro de `Manuales/`:
> ```bash
> git remote add origin git@github.com:marko-boochan/manuales-boochan.git
> git push -u origin main
> ```
> No pedirá contraseña.

> [!example] Paso 2 (🔐 vía HTTPS + token) — Alternativa
> Crea un token: **Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate**, con permiso **`repo`**; cópialo. Luego, dentro de `Manuales/`:
> ```bash
> git remote add origin https://github.com/marko-boochan/manuales-boochan.git
> git push -u origin main
> ```
> Cuando pida contraseña, **pega el token** (no tu contraseña normal).

> [!example] Paso 3 — Verifica
> Refresca GitHub: el repositorio `manuales-boochan` debe aparecer con tu `README.md`.

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Marcaste "Add a README" al crear el repo | El `push` es rechazado (repo no vacío) | Créalo vacío, o haz `git pull --rebase` y reintenta. |
> | `Permission denied (publickey)` (SSH) | La clave no está bien | Repasa el Paso 2 SSH, o usa la vía HTTPS + token. |
> | Pones tu contraseña normal en HTTPS | GitHub la rechaza | En HTTPS se usa el **token** como contraseña. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - La URL `manuales-boochan` carga en el navegador y muestra el README.
> - `git remote -v` devuelve dos líneas con `origin`.
> - Lo publicado es el **repositorio de manuales**, no la bóveda entera.

> 2. ¿Qué dos vías hay para autenticar y en qué se diferencian?
> 3. En la vía HTTPS, ¿qué pones como contraseña?

- **Entregable GitHub:** repo `manuales-boochan` (privado, con colaboradores) y commit inicial visible.
- **Entregable bóveda:** sin cambios nuevos en los ficheros; ahora también en GitHub.
- **Criterio de éxito:** el repo carga en el navegador y `git remote -v` muestra `origin`.
