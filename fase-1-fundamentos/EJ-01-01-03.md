## EJ-01-01-03 — Marko crea su bóveda y su primer repositorio de manuales

> [!info] Situación
> Segundo día de Marko en Boochan Networks. Lucía le explica: *"Carlos sabe instalar el servidor Ubuntu de memoria, pero no lo ha escrito en ningún sitio. Si se va de vacaciones, nadie más sabe hacerlo. Empieza a documentar los procedimientos, y llévalo con Git desde el principio."* Marko va a montar su bóveda de trabajo y a convertir en repositorio la carpeta donde guardará los manuales.

- **🎯 Objetivo real:** convertir una carpeta concreta (`Manuales`) en un repositorio Git con `git init`, entendiendo qué es `.git/` y por qué NO se hace sobre la bóveda entera.
- **🧩 Problema que resuelve:** sin `git init` no hay historial; pero versionar la bóveda **entera** rompería los repos que vivirán dentro. Por eso se versiona **cada carpeta de trabajo por separado**.

---

## 📚 Fundamento

> [!info] Antes de empezar: carpeta normal vs repositorio Git
> Una carpeta normal solo contiene archivos; Windows la copia o borra, pero no recuerda su historia. Un **repositorio Git** es una carpeta normal más una zona oculta, `.git/`, donde Git guarda la información para seguir los cambios y crear historial.

> [!danger] La regla de oro: NUNCA `git init` en la bóveda
> `Boveda_Marko/` es el **contenedor**: no se versiona. Dentro habrá varias carpetas que sí son repositorios (`Bitacora/`, `Manuales/`…). Si versionaras la bóveda entera, esos repos quedarían "unos dentro de otros" y se romperían. Regla: **`git init` solo dentro de la carpeta de trabajo** (hoy, `Manuales/`).

> [!tip] Mapa mental de lo que vas a crear
> ```
> Boveda_Marko/         ← contenedor, SIN .git
> ├── Bitacora/         ← (repo, más adelante)
> └── Manuales/         ← HOY: git init aquí → aparece .git/
> ```
> Si borras `.git/`, no pierdes tus archivos visibles, pero sí el historial.

> [!example] Vocabulario de esta práctica
> - **`git init`:** convierte una carpeta en repositorio.
> - **`.git/`:** carpeta oculta donde Git guarda el historial.
> - **Untracked:** archivo que Git ve pero aún no controla.

## 🛠️ Procedimiento

> [!example] Paso 1 — Crea la estructura de la bóveda de Marko
> En tu carpeta base (fuera de OneDrive):
>
> *🐧 Git Bash / Linux*
> ```bash
> cd ~
> mkdir -p Boveda_Marko/Bitacora/Bloque_1_Fundamentos_Git
> mkdir -p Boveda_Marko/Manuales
> cd Boveda_Marko/Manuales
> ```
> *🪟 PowerShell*
> ```powershell
> cd $env:USERPROFILE
> mkdir Boveda_Marko\Bitacora\Bloque_1_Fundamentos_Git
> mkdir Boveda_Marko\Manuales
> cd Boveda_Marko\Manuales
> ```

> [!example] Paso 2 — Comprueba que estás DENTRO de `Manuales`
> *🐧 Git Bash / Linux*
> ```bash
> pwd    # debe terminar en .../Boveda_Marko/Manuales
> ```
> *🪟 PowerShell*
> ```powershell
> pwd    # debe terminar en \Boveda_Marko\Manuales
> ```

> [!example] Paso 3 — Inicializa el repositorio
> (Idéntico en las dos terminales.)
> ```
> git init
> git branch -M main
> ```
> Debe aparecer: `Initialized empty Git repository in .../Manuales/.git/`

> [!example] Paso 4 — Crea un `README.md` de portada
> Por terminal **o** directamente en Obsidian (clic derecho → *New note*):
>
> *🐧 Git Bash / Linux*
> ```bash
> touch README.md
> ```
> *🪟 PowerShell*
> ```powershell
> New-Item README.md -ItemType File
> ```

> [!example] Paso 5 — Escribe la portada y comprueba el estado
> Edita `README.md`:
> ```
> # Manuales — Boochan Networks
> Procedimientos de administración de sistemas documentados por Marko.
> ```
> Y mira el estado:
> ```
> git status
> ```
> `README.md` aparece como **"Untracked file"**.

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Haces `git init` en `Boveda_Marko` | Versionas la bóveda entera (mal) | Comprueba con `pwd` que estás en `.../Manuales` antes. |
> | No ves la carpeta `.git/` | Está oculta | Git Bash: `ls -a`; PowerShell: `Get-ChildItem -Force`. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - `git status` dentro de `Manuales/` no dice "no es un repositorio".
> - En `Boveda_Marko/` **no** hay `.git/` (solo en `Manuales/`).
> - `README.md` existe con contenido.
