## EJ-01-01-04 — Marko hace su primer commit (manual de Ubuntu Server)

> [!info] Situación
> Lucía: *"El primer manual que necesitamos es cómo instalamos Ubuntu Server en `srv-boochan-01`. Carlos lo hace de memoria pero nadie más sabe. Empieza por eso."* Marko crea el manual dentro de su repositorio `Manuales/` y necesita guardarlo con Git.

- **🎯 Objetivo real:** aprender el ciclo `add → commit`: pasar un archivo de "untracked" a "versionado" y guardar una "fotografía" del trabajo con un mensaje claro.
- **🧩 Problema que resuelve:** sin commits, los cambios se pierden si el archivo se modifica o se borra. Cada commit es un punto al que siempre se puede volver.

---

## 📚 Fundamento

> [!info] Antes de empezar: Git tiene TRES zonas
> Cuando trabajas con Git, un archivo pasa por tres sitios. Entender esto es la base de todo:
> 1. **Directorio de trabajo** — tu carpeta normal, donde editas los archivos.
> 2. **Área de preparación (staging / index)** — una "sala de espera" donde pones lo que quieres guardar en el próximo commit. Ahí llegan los archivos con `git add`.
> 3. **Repositorio (historial)** — donde quedan guardadas las "fotos" definitivas. Ahí llegan con `git commit`.
>
> El recorrido es siempre el mismo: **editas → `git add` (a la sala de espera) → `git commit` (foto guardada)**.

> [!abstract] Idea clave: un commit es una foto con etiqueta
> Un **commit** es una fotografía del estado de tus archivos en un momento concreto, con un **mensaje** que la etiqueta ("qué hice y por qué"). Igual que en un álbum con pie de foto, un buen mensaje te permite encontrar el momento exacto meses después, sin abrir cada archivo.

> [!tip] Mapa mental del ciclo
> ```
> [editas el manual]  →  git add  →  [sala de espera]  →  git commit  →  [historial]
>                                                                            │
>                                                                    git log lo muestra
> ```
> `git status` te dice, en cada momento, en qué zona está cada archivo.

> [!example] Vocabulario de esta práctica
> - **Untracked:** archivo que Git ve pero aún no controla.
> - **Staging / index (área de preparación):** la sala de espera; lo que entrará en el próximo commit.
> - **`git add`:** mueve cambios a la sala de espera.
> - **Commit:** foto guardada del trabajo, con su mensaje.
> - **`git log`:** lista el historial de commits.

## 🛠️ Procedimiento

> [!example] Paso 1 — Sitúate en tu repositorio de manuales
> *🐧 Git Bash / Linux*
> ```bash
> cd ~/Boveda_Marko/Manuales
> ```
> *🪟 PowerShell*
> ```powershell
> cd $env:USERPROFILE\Boveda_Marko\Manuales
> ```

> [!example] Paso 2 — Crea las carpetas temáticas dentro de `Manuales/`
> *🐧 Git Bash / Linux*
> ```bash
> mkdir 00_infraestructura 01_linux_server 02_active_directory 03_almacenamiento 04_red 05_seguridad 06_integracion_windows
> ```
> *🪟 PowerShell*
> ```powershell
> mkdir 00_infraestructura, 01_linux_server, 02_active_directory, 03_almacenamiento, 04_red, 05_seguridad, 06_integracion_windows
> ```

> [!example] Paso 3 — Crea el fichero del manual
> Por terminal **o** directamente en Obsidian (clic derecho → *New note*):
>
> *🐧 Git Bash / Linux*
> ```bash
> touch 01_linux_server/instalacion_ubuntu.md
> ```
> *🪟 PowerShell*
> ```powershell
> New-Item 01_linux_server\instalacion_ubuntu.md -ItemType File
> ```

> [!example] Paso 4 — Escribe el esqueleto del manual
> Edita `01_linux_server/instalacion_ubuntu.md` con este contenido:
> ```
> # Instalación de Ubuntu Server LTS en srv-boochan-01
>
> ## Objetivo
> Desplegar Ubuntu Server 24.04 LTS en una VM Azure que servirá de base para
> los servicios de Boochan Networks.
>
> ## Requisitos
> - Cuenta Azure activa
> - Tamaño VM: Standard_B2s (2 vCPU, 4 GB RAM)
> - Imagen: Ubuntu Server 24.04 LTS Gen2
>
> ## Pasos
> 1. Acceder a portal.azure.com.
> 2. Crear máquina virtual.
> 3. (Pendiente: completar pasos detallados)
> ```

> [!example] Paso 5 — Mira en qué zona está el archivo
> ```
> git status
> ```
> Aparece en rojo como **"Untracked"**: Git lo ve, pero aún no lo controla.

> [!example] Paso 6 — Muévelo a la sala de espera
> ```
> git add .
> ```

> [!example] Paso 7 — Comprueba que ya está preparado
> ```
> git status
> ```
> Ahora aparece en verde como **"Changes to be committed"**.

> [!example] Paso 8 — Haz la foto (commit) con un mensaje claro
> ```
> git commit -m "EJ-01-01-04 · Estructura inicial de Manuales + manual base de Ubuntu Server"
> ```

> [!example] Paso 9 — Mira el historial
> ```
> git log --oneline
> ```
> Debe aparecer tu commit.

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Olvidas `git add` antes del commit | Git dice "nothing to commit" | Haz siempre `git status` antes: si no hay nada en verde, falta el `add`. |
> | Mensaje vago (`git commit -m "cosas"`) | Dentro de un mes no sabrás qué hiciste | Describe **qué** y **por qué**: "manual Ubuntu: añadida sección X". |
> | Commiteas un secreto (contraseña, `.pem`) | Queda en el historial para siempre | Nunca metas credenciales; en el EJ-01-02-03 aprenderás a excluirlas con `.gitignore`. |

> [!danger] Si Git te pide nombre y correo al commitear
> Significa que el **EJ-01-01-02** (identidad) no se completó. Párate, vuelve a configurar `user.name` y `user.email`, y repite el commit.

> [!success] ✅ Verificación: ¿está bien hecho?
> - `git status` queda **limpio** ("nothing to commit, working tree clean").
> - `git log --oneline` muestra **al menos 1 commit** con tu mensaje "EJ-01-01-04 · ...".
> - Las 7 carpetas y el manual existen dentro de `Manuales/`.
> - La bóveda `Boveda_Marko/` **sigue sin** carpeta `.git/` (solo la tiene `Manuales/`).
