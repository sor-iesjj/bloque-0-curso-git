> [!info] Situación
> Lucía pasa por la mesa de Marko: *"Muy bien, ya tienes el manual guardado en tu ordenador. Pero si se te rompe el portátil, se pierde. Súbelo a GitHub para que quede a salvo y para que Carlos y yo podamos verlo."* Marko conecta su repositorio local con uno remoto y lo publica. Como es la primera vez, elige **cómo va a autenticarse**.

- **🎯 Objetivo real:** crear un repositorio remoto y enlazar el local con `git remote add` + `git push -u`, aprendiendo **las dos formas de autenticar**: SSH y HTTPS + token.
- **🧩 Problema que resuelve:** si el portátil se rompe, el trabajo se pierde. GitHub es el backup y el punto donde el equipo consulta la documentación.

---

## 📚 Fundamento

> [!info] Antes de empezar: local y remoto
> Hasta ahora tu repositorio `Manuales/` vivía **solo en tu ordenador**. Publicar es conectar ese repo local con un **repositorio remoto** en GitHub (llamado `origin`) y **subir** tus commits con `push`. A partir de ahí, GitHub es la "copia maestra" accesible desde cualquier sitio.

> [!warning] Publicamos el REPOSITORIO, no la bóveda
> Subes `Manuales/` (que se llamará `manuales-boochan-cole` en GitHub), **no** `Boveda_Git_Cole/`. La bóveda contenedor nunca se sube entera.

> [!abstract] Idea clave: un repo, dos formas de autenticar
> Para que GitHub sepa que eres tú, necesitas identificarte. Hay **dos vías** (elige una; puedes probar las dos):
> - 🔑 **SSH** (recomendada): se configura una vez con una clave, no pide contraseña, no caduca.
> - 🔐 **HTTPS + token**: usas un *Personal Access Token* como contraseña; más simple, pero caduca.

> [!example] Vocabulario de esta práctica
> - **Remoto / `origin`:** el repositorio en GitHub al que se conecta tu repo local.
> - **`git remote add`:** enlaza local ↔ remoto.
> - **`git push -u origin main`:** sube y deja enlazada la rama.
> - **Token (PAT):** contraseña temporal para la vía HTTPS.

> [!example] Paso 2 (🔑 vía SSH, recomendada) — Configura la clave y sube
> Tu clave SSH ya está puesta desde la **Bloque 0 · Fase 0.2.2**. Abre la terminal **sobre `Manuales`** y comprueba dónde estás:
> ```bash
> pwd
> git remote -v
> ```
> **Línea por línea:** `pwd` muestra dónde estás; `git remote -v` consulta si ya hay un destino configurado.
>
> ✅ **Sigue si** la ruta termina en `Boveda_Git_Cole/Manuales` y `git remote -v` **no devuelve nada**: este repositorio aún no tiene remoto.
> 🛑 **Para si** `git remote -v` ya nombra algún repositorio: no estás en `Manuales`.
>
> Conéctalo y sube. **Cambia `TU-USUARIO` por tu usuario de GitHub:**
> ```bash
> git remote add origin git@github.com:TU-USUARIO/manuales-boochan-cole.git
> git remote -v
> git push -u origin main
> ```
> **Línea por línea:** `git remote add` conecta `Manuales` con el repositorio remoto; `git remote -v` permite revisar la dirección; `git push -u` sube la rama y recuerda su seguimiento. La segunda línea debe nombrar `manuales-boochan-cole`.

> [!example] Paso 2 (🔐 vía HTTPS + token) — Alternativa
> Crea un token: **Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate**, con permiso **`repo`**; cópialo. Luego, dentro de `Manuales/`:
> ```bash
> pwd
> git remote add origin https://github.com/TU-USUARIO/manuales-boochan-cole.git
> git remote -v
> git push -u origin main
> ```
> **Línea por línea:** `pwd` comprueba que sigues en `Manuales`; `git remote add` conecta el remoto HTTPS; `git remote -v` permite revisarlo antes de subir; `git push -u` publica la rama. Cuando GitHub pida contraseña, **pega el token** (no tu contraseña normal).

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Marcaste "Add a README" al crear el repo | El `push` es rechazado (repo no vacío) | Créalo vacío, o haz `git pull --rebase` y reintenta. |
> | `Permission denied (publickey)` (SSH) | La clave no está bien | Repasa la **Bloque 0 · Fase 0.2.2**, o usa la vía HTTPS + token. |
> | Pones tu contraseña normal en HTTPS | GitHub la rechaza | En HTTPS se usa el **token** como contraseña. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - La URL `manuales-boochan-cole` carga en el navegador y muestra el README.
> - `git remote -v` devuelve dos líneas con `origin`.
