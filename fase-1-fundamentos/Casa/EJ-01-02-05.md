## 📚 Fundamento

> [!info] Antes de empezar: clonar es "bajar una copia completa"
> `git clone` descarga **todo** un repositorio: sus archivos **y su historial**. No es como bajar un ZIP: te traes también todos los commits, para poder consultarlos con `git log`. Además, al clonar, Git ya deja configurada la conexión (`origin`) con el repo original.

> [!abstract] Idea clave: un repo, dos puertas
> El repositorio es **uno**: `sor-iesjj/scripts-utiles`, público. Con ese mismo repo puedes entrar por **SSH** (`git@github.com:...`) o por **HTTPS** (`https://github.com/...`): es la misma casa por dos puertas. Usa la vía que montaste al preparar el entorno.

> [!example] Vocabulario de esta práctica
> - **`git clone`:** descarga por primera vez un repositorio a tu ordenador.
> - **`origin`:** el nombre que Git le da al repositorio remoto de origen.
> - **Permiso de lectura:** puedes ver y clonar, pero no subir cambios (`push`) al repo de otro.

> **Barrera de ubicación antes de los comandos:** sitúate en el contenedor `Boveda_Git_Casa` y ejecuta este bloque primero:
> ```bash
> pwd -P
> ruta=$(pwd -P | tr '[:upper:]' '[:lower:]')
> case "$ruta" in
>   */sor|*/sor/*|*/boveda_sor|*/boveda_sor/*) echo "ERROR: ubicación dentro de SOR; detente"; exit 1 ;;
>   */sor_git_casa/boveda_git_casa) echo "Contenedor neutral correcto" ;;
>   *) echo "ERROR: ruta o contexto incorrectos; detente"; exit 1 ;;
> esac
> if git rev-parse --show-toplevel >/dev/null 2>&1; then echo "ERROR: el contenedor hereda un repositorio Git; detente"; exit 1; fi
> ```
> `pwd -P` muestra la ruta física; `tr` normaliza mayúsculas/minúsculas; `case` bloquea ancestros llamados exactamente `SOR` o `Boveda_SOR` y admite solo la bóveda correcta. `git rev-parse` confirma que no estás dentro de otro repositorio. Continúa solo si aparece `Contenedor neutral correcto`.
