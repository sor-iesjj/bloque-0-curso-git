> [!info] Situación

Súbelo a GitHub para que quede a salvo y para que Carlos y yo podamos verlo."* Marko conecta su repositorio local con uno remoto y lo publica. Como es la primera vez, elige **cómo va a autenticarse**.

- **🎯 Objetivo real:** crear un repositorio remoto y enlazar el local con `git remote add` + `git push -u`, aprendiendo **las dos formas de autenticar**: SSH y HTTPS + token.
- **🧩 Problema que resuelve:** si el portátil se rompe, el trabajo se pierde. GitHub es el backup y el punto donde el equipo consulta la documentación.

## 📚 Fundamento

> [!info] Antes de empezar: local y remoto
> Hasta ahora tu repositorio `Manuales/` vivía **solo en tu ordenador**. Publicar es conectar ese repo local con un **repositorio remoto** en GitHub (llamado `origin`) y **subir** tus commits con `push`. A partir de ahí, GitHub es la "copia maestra" accesible desde cualquier sitio.

> [!warning] Publicamos el REPOSITORIO, no la bóveda
> Subes `Manuales/` (que se llamará `manuales-boochan-casa` en GitHub), **no** `SOR_Git_Casa/Boveda_Git_Casa/`. La bóveda contenedor nunca se sube entera.

> [!abstract] Idea clave: un repo, dos formas de autenticar
> Para que GitHub sepa que eres tú, necesitas identificarte. Hay **dos vías** (elige una; puedes probar las dos):
> - 🔑 **SSH** (recomendada): se configura una vez con una clave, no pide contraseña, no caduca.
> - 🔐 **HTTPS + token**: usas un *Personal Access Token* como contraseña; más simple, pero caduca.

> [!example] Vocabulario de esta práctica
> - **Remoto / `origin`:** el repositorio en GitHub al que se conecta tu repo local.
> - **`git remote add`:** enlaza local ↔ remoto.
> - **`git push -u origin main`:** sube y deja enlazada la rama.
> - **Token (PAT):** contraseña temporal para la vía HTTPS.

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Marcaste "Add a README" al crear el repo | El `push` es rechazado (repo no vacío) | Créalo vacío, o haz `git pull --rebase` y reintenta. |
> | `Permission denied (publickey)` (SSH) | La clave no está bien | Repasa la **Bloque 0 · Fase 0.2.2**, o usa la vía HTTPS + token. |
> | Pones tu contraseña normal en HTTPS | GitHub la rechaza | En HTTPS se usa el **token** como contraseña. |
