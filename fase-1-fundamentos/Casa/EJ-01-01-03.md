- **🎯 Objetivo real:** convertir una carpeta concreta (`Manuales`) en un repositorio Git con `git init`, entendiendo qué es `.git/` y por qué NO se hace sobre la bóveda entera.
- **🧩 Problema que resuelve:** sin `git init` no hay historial; pero versionar la bóveda **entera** rompería los repos que vivirán dentro. Por eso se versiona **cada carpeta de trabajo por separado**.

---

## 📚 Fundamento

> [!info] Antes de empezar: carpeta normal vs repositorio Git
> Una carpeta normal solo contiene archivos; Windows la copia o borra, pero no recuerda su historia. Un **repositorio Git** es una carpeta normal más una zona oculta, `.git/`, donde Git guarda la información para seguir los cambios y crear historial.

> [!danger] La regla de oro: NUNCA `git init` en la bóveda
> `Boveda_Git_Casa/` es el **contenedor**: no se versiona. Dentro hay varias carpetas que sí son repositorios (`B0_Curso_Git_Casa/`, `Bitacora/` y, desde hoy, `Manuales/`). Si versionaras la bóveda entera, esos repos quedarían "unos dentro de otros" y se romperían. Regla: **`git init` solo dentro de la carpeta de trabajo** (hoy, `Manuales/`).

> [!tip] Mapa mental de lo que vas a crear
> ```
> Boveda_Git_Casa/         ← contenedor, SIN .git
> ├── B0_Curso_Git_Casa/     ← repo: el material (ya lo tienes)
> ├── Bitacora/         ← repo: tus apuntes (ya lo tienes)
> └── Manuales/         ← HOY: git init aquí → aparece .git/
> ```
> Si borras `.git/`, no pierdes tus archivos visibles, pero sí el historial.

> [!example] Vocabulario de esta práctica
> - **`git init`:** convierte una carpeta en repositorio.
> - **`.git/`:** carpeta oculta donde Git guarda el historial.
> - **Untracked:** archivo que Git ve pero aún no controla.

> [!example] Paso 3 — Inicializa el repositorio
> (Idéntico en las dos terminales.)
> ```
> git init
> git branch -M main
> ```
> **Línea por línea:** `git init` crea el historial dentro de `Manuales`; `git branch -M main` da a la rama inicial el nombre `main`.
>
> Debe aparecer: `Initialized empty Git repository in .../Manuales/.git/`
>
> Configura tu identidad real **solo en este repositorio** antes de crear el primer commit. Usa tu nombre real y un correo asociado y verificado en GitHub o la dirección `noreply` que figura en `Settings → Emails`; no escribas los datos de Marko ni cambies la configuración global:
> ```bash
> git config --local user.name "TU NOMBRE Y APELLIDOS"
> git config --local user.email "CORREO VERIFICADO O NOREPLY DE GITHUB"
> git config --local --list
> ```
> **Línea por línea:** los dos primeros comandos guardan tu identidad solo en este repositorio; `--list` permite comprobar el resultado. Comprueba que el nombre y el correo verificado o `noreply` son los tuyos.

> [!example] Paso 4 — Crea un `README.md` de portada
> Por terminal **o** directamente en Obsidian (clic derecho → *New note*):
>
> *🐧 Git Bash / Linux*
> ```bash
> touch README.md
> ```
> *🪟 PowerShell*
> ```powershell
> New-Item README.md -ItemType File
> ```

> [!example] Paso 5 — Escribe la portada y comprueba el estado

> `touch` crea un archivo vacío; `New-Item` hace lo mismo en PowerShell. Después de escribir el contenido, `git status` debería mostrar `README.md` como **"Untracked file"**.

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Haces `git init` en `Boveda_Git_Casa` | Versionas la bóveda entera, con los otros dos repos dentro | Comprueba con `pwd` que estás en `.../Manuales` antes. Si ya lo has hecho: borra la carpeta `.git` de `Boveda_Git_Casa` (`rm -rf .git` **estando en `Boveda_Git_Casa`**) y repite. |
> | No ves la carpeta `.git/` | Está oculta | Git Bash: `ls -a`; PowerShell: `Get-ChildItem -Force`. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - `git status` dentro de `Manuales/` no dice "no es un repositorio".
> - En `Boveda_Git_Casa/` **no** hay `.git/` (solo en `Manuales/`).
> - `README.md` existe con contenido.
