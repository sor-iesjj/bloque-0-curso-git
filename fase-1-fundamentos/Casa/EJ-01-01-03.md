Si se va de vacaciones, nadie más sabe hacerlo. - **🎯 Objetivo real:** convertir una carpeta concreta (`Manuales`) en un repositorio Git con `git init`, entendiendo qué es `.git/` y por qué NO se hace sobre la bóveda entera.
- **🧩 Problema que resuelve:** sin `git init` no hay historial; pero versionar la bóveda **entera** rompería los repos que vivirán dentro. Por eso se versiona **cada carpeta de trabajo por separado**.

---

## 📚 Fundamento

> [!info] Antes de empezar: carpeta normal vs repositorio Git
> Una carpeta normal solo contiene archivos; Windows la copia o borra, pero no recuerda su historia. Un **repositorio Git** es una carpeta normal más una zona oculta, `.git/`, donde Git guarda la información para seguir los cambios y crear historial.

> [!danger] La regla de oro: NUNCA `git init` en la bóveda
> `SOR_Git_Casa/Boveda_Git_Casa/` es el **contenedor**: no se versiona. Dentro hay varias carpetas que sí son repositorios (`B0_Curso_Git_Casa/`, `Bitacora/` y, desde hoy, `Manuales/`). Si versionaras la bóveda entera, esos repos quedarían "unos dentro de otros" y se romperían. Regla: **`git init` solo dentro de la carpeta de trabajo** (hoy, `Manuales/`).

> [!tip] Mapa mental de lo que vas a crear
> ```
> SOR_Git_Casa/Boveda_Git_Casa/         ← contenedor, SIN .git
> ├── B0_Curso_Git_Casa/     ← repo: el material (ya lo tienes)
> ├── Bitacora/         ← repo: tus apuntes (ya lo tienes)
> └── Manuales/         ← HOY: git init aquí → aparece .git/
> ```
> Si borras `.git/`, no pierdes tus archivos visibles, pero sí el historial.

> [!example] Vocabulario de esta práctica
> - **`git init`:** convierte una carpeta en repositorio.
> - **`.git/`:** carpeta oculta donde Git guarda el historial.
> - **Untracked:** archivo que Git ve pero aún no controla.

> **Línea por línea:** los dos primeros comandos guardan tu identidad solo en este repositorio; `--list` permite comprobar el resultado. Comprueba que el nombre y el correo verificado o `noreply` son los tuyos.
