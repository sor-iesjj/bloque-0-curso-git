## 📚 Fundamento

> [!info] Antes de empezar: Git guarda todo en un "almacén de objetos"
> Dentro de `.git/` Git guarda cada commit, cada versión de cada archivo, etc., como **objetos**. Con el tiempo ese almacén crece y se desordena. Hay dos tareas de mantenimiento:
> - **`git fsck`** → revisa que no haya objetos **corruptos** (como un "chequeo de disco").
> - **`git gc`** → *garbage collection*: reorganiza objetos y limpia algunos objetos que ya no están referenciados; no garantiza que el repositorio ocupe menos.

> [!abstract] Idea clave: mantenimiento preventivo
> `git gc` mantiene el almacén local; no elimina commits que sigan referenciados por ramas o etiquetas, aunque puede limpiar objetos sin referencia cuando ya ha pasado el plazo de seguridad. `git fsck` comprueba la estructura; un objeto "dangling" no significa necesariamente corrupción.

> [!example] Vocabulario de esta práctica
> - **`git fsck`:** comprueba la integridad de los objetos.
> - **`git gc`:** empaqueta y comprime el repositorio (garbage collection).
> - **`git count-objects -v`:** muestra cuánto ocupa el almacén.
