> - **📹 Nombre del vídeo:** `F1.2.3 · Marko crea su .gitignore (no subir basura)`

> [!info] Situación
> Marko ha visto que en su carpeta hay un `.DS_Store` (de cuando trabajó desde el Mac de su hermano), un `temp.log` y unas notas personales `secretos.txt` con su contraseña Wi-Fi. **NO** quiere subir nada de esto a GitHub.

- **🎯 Objetivo real:** crear un `.gitignore` que excluya archivos temporales, basura del sistema y datos sensibles.
- **🧩 Problema que resuelve:** sin `.gitignore`, archivos sensibles acaban en GitHub. Una contraseña filtrada puede comprometer toda la infraestructura.

---

## 📚 Fundamento

> [!info] Antes de empezar: qué es `.gitignore`
> Es un archivo de texto donde escribes **una lista de cosas que Git debe ignorar**. Todo lo que coincida con esa lista, Git lo trata como si no existiera: no lo versiona ni lo sube. Es la **primera línea de defensa** contra subir basura o secretos sin querer.

> [!abstract] Idea clave: lo que sube a GitHub es para siempre
> Un secreto (contraseña, clave `.pem`) que se sube a GitHub **queda en el historial aunque luego lo borres**. Por eso se evita **antes** de que ocurra, con `.gitignore`, no después.

> [!example] Vocabulario de esta práctica
> - **`.gitignore`:** archivo con la lista de lo que Git ignora.
> - **Patrón `*.log`:** el `*` significa "cualquier texto"; `*.log` = todos los archivos que acaben en `.log`.
> - **`#`:** una línea que empieza por `#` es un comentario (Git no la aplica).

> [!example] Paso 1 — Crea archivos de prueba (para ver el efecto)
> *🐧 Git Bash / Linux*
> ```bash
> touch temp.log secretos.txt .DS_Store
> ```
> *🪟 PowerShell*
> ```powershell
> New-Item temp.log, secretos.txt, .DS_Store -ItemType File
> ```

> [!example] Paso 2 — Crea el archivo `.gitignore`
> *🐧 Git Bash / Linux*
> ```bash
> touch .gitignore
> ```
> *🪟 PowerShell*
> ```powershell
> New-Item .gitignore -ItemType File
> ```

> [!example] Paso 3 — Escribe las reglas
> Edita `.gitignore` (en Obsidian o tu editor) con este contenido:
> ```
> # Sistema
> .DS_Store
> Thumbs.db
> desktop.ini
>
> # Logs y temporales
> *.log
> *.tmp
> *~
>
> # Secretos (NUNCA subir)
> secretos.txt
> .env
> *.key
> *.pem
>
> # Editores
> .vscode/
> .idea/
>
> # Vídeos (pesan mucho, no van al repo)
> *.mp4
> *.mkv
> ```

> [!example] Paso 4 — Comprueba que Git ya los ignora
> ```
> git status
> ```
> `temp.log`, `secretos.txt` y `.DS_Store` **NO** deben aparecer.

> [!example] Paso 5 — Guarda y sube el `.gitignore`
> ```
> git add .gitignore
> git commit -m "EJ-01-02-03 · Añadido .gitignore (protege secretos y excluye basura)"
> git push
> ```

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | El archivo YA estaba versionado antes del `.gitignore` | `.gitignore` no lo borra de Git | Sácalo con `git rm --cached <archivo>` y luego commit. |
> | Pones el secreto en el repo "solo un momento" | Ya queda en el historial | Nunca lo subas: primero el `.gitignore`, luego trabajas. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - `git status` **no** muestra los archivos sensibles.
> - En GitHub **no** aparecen `temp.log`, `secretos.txt` ni `.DS_Store`.
