## 📚 Fundamento

> [!info] Por qué un técnico verifica antes de empezar
> En cualquier trabajo serio de sistemas, lo primero no es hacer: es **comprobar que se puede hacer**. Los pilotos tienen una lista de verificación antes de despegar y la repasan **aunque el avión funcionara ayer**.
>
> Aquí es lo mismo. Cinco comprobaciones, y cada una responde a una pregunta concreta:
>
> | Compruebo | Respondo a |
> | :--- | :--- |
> | `git --version` | ¿Está Git instalado y es lo bastante reciente? |
> | `git config --list` | ¿Sabe Git quién soy? ¿Con qué nombre firmo mis commits? |
> | `ssh -T git@github.com` | ¿Me reconoce GitHub sin pedirme la contraseña? |
> | Mi repo en GitHub | ¿Tengo dónde subir el trabajo? |
> | `git log` en mi repo | ¿He hecho commits de verdad, o solo he leído sobre ellos? |

> [!warning] El fallo nº1: el correo mal puesto
> Es el que más se repite y el más silencioso. Si `user.email` está mal escrito o es distinto del de tu cuenta de GitHub, **todo funciona**: puedes hacer commits y subirlos sin ningún error.
>
> Lo que pasa es que GitHub **no te reconoce como autor**: tus commits aparecen a nombre de un usuario fantasma, sin tu foto, y **no cuentan en tu perfil**. Cuando te das cuenta llevas dos meses y cuarenta commits huérfanos que ya no se arreglan.
>
> Por eso este ejercicio existe.

> [!example] Vocabulario de esta práctica
> - **Verificación:** comprobar que algo funciona **antes** de necesitarlo.
> - **`git config --list`:** muestra toda la configuración de Git activa en tu equipo.
> - **`--global`:** la configuración vale para **todos** tus repositorios, no solo el actual.
> - **Clave SSH:** la pareja de claves que te identifica ante GitHub sin contraseña.

## 🛠️ Procedimiento

> [!example] Paso 0 — Prepárate y empieza a grabar
> Ten abierta una terminal (**Git Bash** en Windows, **Terminal** en Linux) y una pestaña con tu **perfil de GitHub**. Arranca OBS y preséntate.

> [!example] Comprobación 1 — ¿Está Git instalado?
> ```bash
> git --version
> ```
> ✅ **Bien si** devuelve una versión **2.40 o superior**.
> ❌ **Si dice `command not found`:** no está instalado o has abierto el `cmd` en vez de Git Bash. → **Fase 0.2.1** de prerrequisitos, que trae la nota de instalación para Windows y Linux.

> [!example] Comprobación 2 — ¿Sabe Git quién eres? *(la importante)*
> ```bash
> git config --global user.name
> git config --global user.email
> ```
> ✅ **Bien si** salen tu nombre y tu correo, **y el correo es el mismo que el de tu cuenta de GitHub**.
>
> Compruébalo de verdad, no de memoria: entra en `github.com` → tu foto → **`Settings`** → **`Emails`**, y compara **carácter a carácter**.
>
> ❌ **Si están vacíos o mal:**
> ```bash
> git config --global user.name "Tu Nombre"
> git config --global user.email "el-mismo-de-github@ejemplo.com"
> ```
> → La explicación completa está en la **Fase 0.2.1**.
>
> > [!tip] 💡 Aprovecha y mira toda tu configuración
> > ```bash
> > git config --list
> > ```
> > Salen todos los ajustes activos. **Recuerda: se sale con `q`** — es el paginador, no se ha colgado.

> [!example] Comprobación 3 — ¿Te reconoce GitHub?
> ```bash
> ssh -T git@github.com
> ```
> ✅ **Bien si** responde `Hi TU-USUARIO! You've successfully authenticated...`
> *(Lo de "does not provide shell access" es normal y no es un error.)*
>
> ❌ **Si dice `Permission denied (publickey)`:** no tienes la clave SSH puesta. → **Fase 0.2.2**.
> ❌ **Si se queda colgado y acaba en `timeout`:** el cortafuegos del centro está bloqueando el puerto 22. **Avísame**, tiene solución.

> [!example] Comprobación 4 — ¿Tienes dónde trabajar?
> Abre tu repositorio de apuntes en el navegador y **enséñalo en el vídeo**:
> ```
> https://github.com/TU-USUARIO/apuntes-sor-t1
> ```
> ✅ **Bien si** existe y tiene ficheros dentro.
> ❌ **Si no existe:** aún no has hecho la **Fase 0.3**. No pasa nada — es lo que estamos comprobando. Hazla y vuelve aquí.

> [!example] Comprobación 5 — ¿Has hecho commits de verdad?
> Abre la terminal **dentro de tu repositorio** (clic derecho sobre la carpeta → `Abrir Git Bash aquí`):
> ```bash
> pwd
> git log --oneline
> git status
> ```
> ✅ **Bien si** ves **al menos un commit** con un mensaje que dice algo, y el `status` responde `working tree clean` o `up to date`.
>
> **Lee tus mensajes de commit en voz alta.** ¿Se entiende qué hiciste en cada uno? Si pone `asdf` o `cambios`, ya sabes en qué tienes que mejorar.

> [!example] Paso final — Cierra el vídeo y súbelo
> 1. **Di el veredicto en voz alta:** *"Mi equipo está listo"* o *"me falta X y lo arreglo ahora"*.
> 2. Detén la grabación, nombra el vídeo `F1.1.0 · Marko comprueba su equipo` y súbelo a `Curso Git — Fase 1` (No listado) con timestamps:

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | `git: command not found` | Abriste el `cmd` en vez de Git Bash | Clic derecho → `Abrir Git Bash aquí` |
> | El correo de Git ≠ el de GitHub | Tus commits **no te los cuenta** GitHub y no llevan tu foto | Compáralos **carácter a carácter** en `Settings → Emails` |
> | La pantalla se queda atascada tras `git config --list` | Es el **paginador**, no un cuelgue | Pulsa **`q`** |
> | `Permission denied (publickey)` | No tienes clave SSH en este equipo | Fase 0.2.2. Cada equipo necesita **la suya** |
> | `ssh -T` se queda colgado | El puerto 22 está bloqueado en la red del centro | Avisa al profesor |

> [!success] ✅ Verificación: ¿está bien hecho?
> Las cinco comprobaciones hechas **en pantalla**, con su resultado leído en voz alta, y un veredicto claro al final.

> [!question] Comprueba que lo has entendido
> Responde en tu bitácora:
> 1. ¿Por qué un correo mal puesto en Git es un problema **silencioso**? ¿Cuándo se acaba notando?
> 2. ¿Qué diferencia hay entre que Git te reconozca (`git config`) y que te reconozca GitHub (`ssh -T`)?
> 3. De las cinco comprobaciones, **¿cuál fallaría si cambiaras de ordenador?** ¿Por qué esa y no las otras?
> 4. ¿Por qué un técnico verifica su entorno **aunque ayer funcionara**?
