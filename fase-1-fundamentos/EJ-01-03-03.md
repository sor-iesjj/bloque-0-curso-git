## EJ-01-03-03 — Marko verifica integridad con `git fsck` y limpia con `git gc`

> [!info] Situación
> Lucía le ha pasado a Marko un curso de buenas prácticas con un capítulo sobre **mantenimiento del repositorio**. Marko lo aplica a su repositorio `Manuales`.

- **🎯 Objetivo real:** conocer las herramientas de mantenimiento interno de Git: **detectar corrupción** y **optimizar** el almacén de objetos.
- **🧩 Problema que resuelve:** repos grandes sin mantenimiento se vuelven lentos; y si hay corrupción, `fsck` la detecta antes de que se propague al remoto.

---

## 📚 Fundamento

> [!info] Antes de empezar: Git guarda todo en un "almacén de objetos"
> Dentro de `.git/` Git guarda cada commit, cada versión de cada archivo, etc., como **objetos**. Con el tiempo ese almacén crece y se desordena. Hay dos tareas de mantenimiento:
> - **`git fsck`** → revisa que no haya objetos **corruptos** (como un "chequeo de disco").
> - **`git gc`** → *garbage collection*: **empaqueta y comprime** el almacén para que ocupe menos y vaya más rápido.

> [!abstract] Idea clave: mantenimiento preventivo
> Un técnico no espera a que algo falle: revisa y limpia de vez en cuando. `git gc` es **seguro** (solo reorganiza, no borra tu historia). `git fsck` te avisa a tiempo si algo se ha dañado.

> [!example] Vocabulario de esta práctica
> - **`git fsck`:** comprueba la integridad de los objetos.
> - **`git gc`:** empaqueta y comprime el repositorio (garbage collection).
> - **`git count-objects -v`:** muestra cuánto ocupa el almacén.

---

## 🛠️ Procedimiento
Trabaja dentro de `Manuales/`.

> [!example] Paso 1 — Verifica la integridad
> ```
> git fsck --full
> ```
> Debe responder "Checking objects..." y **sin errores**.

> [!example] Paso 2 — Mira el tamaño actual
> ```
> git count-objects -v
> ```

> [!example] Paso 3 — Empaqueta y limpia
> ```
> git gc --aggressive
> ```

> [!example] Paso 4 — Mira el tamaño después
> ```
> git count-objects -v
> ```
> El valor `size-pack` debería haber bajado.

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Temes que `git gc` borre tu historia | No la borra: solo reorganiza | Es una operación segura de mantenimiento. |
> | Usas `--aggressive` a todas horas | Tarda mucho | Resérvalo para mantenimiento ocasional. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - `git fsck` se ejecuta **sin errores**.
> - El manual de configuración queda ampliado con la sección de mantenimiento.
