## EJ-05-02-01 — Marko crea su primer GitHub Action

> [!info] Situación
> Lucía: *"Quiero que cada PR pase por una validación automática: que los archivos `.md` no tengan errores básicos. Si fallan, NO se fusionan."*

- **🎯 Objetivo real:** crear un **workflow de GitHub Actions** que se ejecute en cada PR.
- **🧩 Problema que resuelve:** sin CI, los errores se descubren cuando alguien usa el manual; con CI, se detectan **antes** del merge.

---

## 📚 Fundamento

> [!info] Antes de empezar: ¿qué es un "GitHub Action" / CI?
> **CI** (Integración Continua) significa que, cada vez que subes cambios, **GitHub ejecuta comprobaciones automáticas** en sus servidores. Un **workflow** es un archivo `.yml` donde describes esas comprobaciones. Aquí, comprobaremos que los `.md` están bien formateados.

> [!abstract] Idea clave: un robot que revisa por ti
> El workflow es un "revisor robot" que nunca se cansa: en cada PR, valida y pone un ✅ o una ❌. Si falla, avisa **antes** de que el error llegue a `main`.

> [!example] Vocabulario de esta práctica
> - **Workflow:** archivo `.yml` en `.github/workflows/` que define las comprobaciones.
> - **`on: pull_request`:** cuándo se ejecuta (aquí, en cada PR).
> - **Checks:** los resultados que aparecen en el PR.

---

## 🛠️ Procedimiento
Dentro de `Manuales/`.

> [!example] Paso 1 — Crea el archivo del workflow
> *🐧 Git Bash / Linux*
> ```bash
> mkdir -p .github/workflows
> touch .github/workflows/validate-md.yml
> ```
> *🪟 PowerShell*
> ```powershell
> New-Item .github\workflows -ItemType Directory -Force
> New-Item .github\workflows\validate-md.yml -ItemType File
> ```

> [!example] Paso 2 — Escribe el workflow
> Edita `.github/workflows/validate-md.yml`:
> ```yaml
> name: Validate Markdown
> on:
>   pull_request:
>     branches: [main, develop]
> jobs:
>   check:
>     runs-on: ubuntu-latest
>     steps:
>       - uses: actions/checkout@v4
>       - name: Markdown lint
>         uses: DavidAnson/markdownlint-cli2-action@v16
>         with:
>           globs: "**/*.md"
> ```

> [!example] Paso 3 — Súbelo
> ```
> git add .github/workflows/validate-md.yml
> git commit -m "EJ-05-02-01 · Workflow CI: validación markdown en PR"
> git push
> ```

> [!example] Paso 4 — Compruébalo
> Abre un PR y ve a la pestaña **"Checks"**: verás la ejecución del workflow (✅ o ❌).

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Colocas el `.yml` fuera de `.github/workflows/` | No se ejecuta | Debe estar en esa carpeta exacta. |
> | Indentación del YAML incorrecta | El workflow falla al cargar | El YAML es sensible a los espacios; respeta la sangría. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - El workflow aparece en la pestaña **"Actions"**.
> - Se ejecuta al abrir un PR.
