## EJ-05-02-04 — Marko crea un Personal Access Token con scope mínimo

> [!info] Situación
> El script de sync nocturno (EJ-05-01-03) deja de funcionar: GitHub ya no permite autenticarse con la contraseña normal. Marko crea un **token** específico.

- **🎯 Objetivo real:** crear un **PAT** (Personal Access Token) con **permisos mínimos** y usarlo en lugar de la contraseña.
- **🧩 Problema que resuelve:** usar la contraseña personal en scripts es inseguro y ya no se permite.

---

## 📚 Fundamento

> [!info] Antes de empezar: una contraseña "de usar y tirar" para máquinas
> Un **token** es como una contraseña especial: se la das a un script o a Git para que se identifique, **sin** usar tu contraseña real. Puedes ponerle **caducidad** y **limitar** lo que puede hacer. Si se filtra, revocas ese token y ya está, sin tocar tu cuenta.

> [!abstract] Idea clave: mínimo privilegio
> Dale al token **solo** los permisos que necesita (aquí, `repo`) y **nada más**. Si un token con permisos mínimos se filtra, el daño posible es menor. Es un principio básico de seguridad.

> [!example] Vocabulario de esta práctica
> - **PAT (Personal Access Token):** contraseña temporal con permisos limitados.
> - **Scope:** el conjunto de permisos del token.
> - **Credential Manager:** dónde guarda Windows el token de forma segura.

---

## 🛠️ Procedimiento

> [!example] Paso 1 — Genera el token
> GitHub → **Settings → Developer settings → Personal access tokens → Tokens (classic) → "Generate new token (classic)"**.

> [!example] Paso 2 — Configúralo con lo mínimo
> - **Note:** `Sync nocturno - manuales-boochan`
> - **Expiration:** 90 días
> - **Scopes:** SOLO **`repo`**

> [!example] Paso 3 — Cópialo YA
> Pulsa **Generate** y **copia el token inmediatamente**: no se vuelve a mostrar.

> [!example] Paso 4 — Guárdalo de forma segura y úsalo
> ```
> git config --global credential.helper manager
> ```
> En el siguiente `git push`, GitHub pedirá usuario y contraseña: pon tu usuario y **pega el token**. Queda guardado en el Credential Manager.

---

## 🚩 Errores y verificación

> [!danger] NUNCA pegues el token en el código
> Un token en un archivo del repo es una fuga de seguridad. Guárdalo **solo** en el Credential Manager o en variables de entorno.

> [!warning] Otros errores típicos
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Le das todos los scopes | Token peligroso si se filtra | Dale solo `repo`. |
> | No lo copias al crearlo | No se vuelve a ver | Cópialo inmediatamente. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - El token está activo.
> - El sync nocturno vuelve a funcionar (push sin pedir contraseña).
