> [!info] Situación
> Carlos avisa: *"Marko, alguien commiteó un archivo `.env` con la contraseña **real** del Active Directory. Está en el commit `a3b2c1d`. Lleva ahí 2 horas."*

- **🎯 Objetivo real:** eliminar el secreto del **histórico**, **rotar** la credencial y proteger el repo.
- **🧩 Problema que resuelve:** borrar el archivo en un commit nuevo **NO basta**: el histórico de Git sigue conteniéndolo.

---

## 📚 Fundamento

> [!danger] Lo PRIMERO: rotar la contraseña, no tocar Git
> Un secreto subido pudo ser ya descargado por bots automáticos en segundos. Por eso, la **primera** acción **siempre** es **cambiar la contraseña** en el sistema afectado (aquí, Active Directory). Limpiar Git viene **después**.

> [!info] Antes de empezar: borrar del presente ≠ borrar del pasado
> Si borras el `.env` con un commit nuevo, desaparece de la versión actual… pero **sigue en el histórico** (cualquiera puede ir a un commit antiguo y verlo). Para quitarlo de verdad hay que **reescribir el histórico** con `git filter-repo`.

> [!example] Vocabulario de esta práctica
> - **Rotar credencial:** cambiar la contraseña/clave comprometida.
> - **`git filter-repo`:** reescribe el histórico para eliminar un archivo de todos los commits.
> - **Post-mortem:** documento que explica qué pasó y cómo se evitará.

> [!example] Paso 1 — Prepara el escenario: provoca la fuga (a propósito)
> En tu repositorio no hay ningún `.env` subido, así que primero lo subes tú. En `Manuales`, en la rama `develop`:
> ```bash
> pwd
> git remote -v
> git switch develop
> echo "AD_PASSWORD=EstaEsInventada123" > .env
> git add -f .env
> git commit -m "EJ-05-03-02 · config del servidor (commit con la fuga, a propósito)"
> git push
> ```
> **La contraseña es inventada. Nunca una real, ni para practicar.**
>
> Fíjate en el `-f`: tu `.gitignore` del **EJ-01-02-03** ya ignoraba `.env`, y por eso `git add .env` a secas no lo habría cogido. **Así ocurren las fugas de verdad:** alguien fuerza el `add` "solo esta vez".

> Es una copia completa, con todas las ramas y etiquetas, **tal como estaba antes de la limpieza**. Si algo sale mal, de aquí se recupera.

> [!example] Paso 5 — Baja un clon limpio para operar
> `git filter-repo` **se niega a trabajar sobre tu `Manuales`**: solo acepta un clon recién hecho, precisamente para que no destroces tu copia de trabajo. En la misma terminal, que sigue en `Boveda_Marko`:
> ```bash
> git clone git@github.com:TU-USUARIO/manuales-boochan.git Manuales_limpio
> cd Manuales_limpio
> pwd
> git remote -v
> ```
> ✅ **Sigue si** la ruta termina en `Boveda_Marko/Manuales_limpio` y el remoto nombra `manuales-boochan`.

> [!example] Paso 6 — Elimina el archivo de TODO el histórico
> ```bash
> git filter-repo --path .env --invert-paths
> git log --all --oneline -- .env
> git remote -v
> ```
> El `git log` ya **no devuelve nada**: `.env` ha desaparecido de todas las ramas. Y el `git remote -v` **tampoco**: `filter-repo` quita el remoto `origin` a propósito, para que no subas un histórico reescrito sin querer.

> [!example] Paso 7 — Reconecta y fuerza la subida a todas las ramas y tags
> ```bash
> git remote add origin git@github.com:TU-USUARIO/manuales-boochan.git
> git remote -v
> ```
>
> 🛑 **Antes de pulsar Intro:** el `git remote -v` de arriba tiene que nombrar `manuales-boochan`, y el `pwd` terminar en `Manuales_limpio`. Lo que viene **sustituye el histórico entero del repositorio de GitHub** y no pide confirmación.
> ```bash
> git push -u origin --force --all
> git push origin --force --tags
> ```
> El `-u` vuelve a enlazar cada rama local con la de GitHub: `filter-repo` había borrado ese enlace junto con el remoto, y sin él tu próximo `git push` a secas fallaría.
>
> > [!warning] ⚠️ Si GitHub rechaza el `push` en `main`
> > Es la protección de rama que pusiste en el **EJ-03-02-05**: impide los `push` forzados, que es justo para lo que está. En un incidente real se desactiva la regla el tiempo imprescindible (**Settings → Branches**), se sube, **y se vuelve a activar**. Anota en tu bitácora cuánto rato ha estado `main` sin proteger.

> [!example] Paso 8 — Sustituye tu `Manuales` por el clon limpio
> Tu carpeta `Manuales` **todavía tiene el secreto** en su histórico. Se retira y ocupa su sitio el clon limpio:
> ```bash
> cd ..
> pwd
> cp Manuales/.git/hooks/commit-msg Manuales_limpio/.git/hooks/
> rm -rf Manuales
> mv Manuales_limpio Manuales
> cd Manuales
> git remote -v
> git log --all --oneline -- .env
> ```
> ✅ **Bien si** la ruta del `pwd` terminaba en `/SOR/Boveda_Marko`, el remoto nombra `manuales-boochan` y el `git log` no devuelve nada.
>
> El `cp` salva el *hook* del **EJ-04-02-05**: vive dentro de `.git/`, que es justo lo que estás tirando. *(Si no hiciste ese ejercicio, la línea dará error y no pasa nada.)*
>
> 🛑 **Lee el `rm -rf` dos veces.** Tiene que poner `Manuales`, y tú tienes que estar en `Boveda_Marko`.

## 🚩 Errores y verificación

> [!danger] Si tocas Git antes de rotar, llegas tarde
> El secreto pudo copiarse ya. La rotación es lo primero, siempre.

> [!warning] `filter-repo` reescribe TODOS los hashes
> Cualquiera con un clon debe re-clonar. Avisa a todo el equipo.

> [!warning] `Aborting: Refusing to destructively overwrite repo history`
> Has lanzado `filter-repo` dentro de `Manuales` en vez de en `Manuales_limpio`. No ha tocado nada: es su seguro. Vuelve al Paso 5.
