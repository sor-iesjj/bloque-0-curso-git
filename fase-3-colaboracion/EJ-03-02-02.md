> [!info] Situación
> El repo original de Lucía ha avanzado, y el fork de Marko se ha quedado atrasado. Marko lo pone al día.

- **🎯 Objetivo real:** mantener un fork **actualizado** con el original (upstream).
- **🧩 Problema que resuelve:** si el fork está desfasado, los PR de Marko chocan con los cambios recientes del original.

---

## 📚 Fundamento

> [!info] Antes de empezar: dos remotos, `origin` y `upstream`
> Tu fork tiene, de fábrica, un remoto: **`origin`** (tu copia). Para poder traer los cambios del original, le añades un segundo remoto: **`upstream`** (el repo de Lucía). Así puedes **bajar del upstream** y **subir a tu origin**.

> [!abstract] Idea clave: primero traer, luego subir
> Sincronizar es: **traer** los cambios del original (`fetch upstream`) → **fusionarlos** en tu rama → **subirlos** a tu fork (`push origin`). GitHub también tiene un botón **"Sync fork"** que hace lo mismo desde la web.

> [!example] Vocabulario de esta práctica
> - **`origin`:** tu fork.
> - **`upstream`:** el repo original.
> - **`git fetch upstream`:** baja los cambios del original sin fusionar todavía.

> [!example] Paso 1 — Añade el remoto `upstream`

> git remote add upstream git@github.com:lucia-boochan/plantillas-procedimientos.git
> git remote -v
> ```
> *(Puedes usar la URL HTTPS `https://github.com/...` si prefieres.)*

> [!example] Paso 2 — Trae los cambios del original
> ```
> git fetch upstream
> ```

> [!example] Paso 3 — Fusiónalos en tu `main`
> ```
> git switch main
> git merge upstream/main
> ```

> [!example] Paso 4 — Sube tu fork actualizado
> ```
> git push origin main
> ```

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Confundes `origin` y `upstream` | Subes o bajas del sitio equivocado | `origin` = tu fork; `upstream` = el original. |
> | Nunca sincronizas | Tus PR entran en conflicto | Sincroniza antes de empezar cambios nuevos. |
