## EJ-03-02-05 — Marko protege la rama `main`

> [!info] Situación
> Lucía: *"Quiero que NADIE pueda pushear directamente a `main`. Todo por PR. Y necesito al menos una aprobación antes de fusionar."*

- **🎯 Objetivo real:** configurar **reglas de protección de rama** en GitHub para hacer **obligatorio** el flujo PR + revisión.
- **🧩 Problema que resuelve:** sin protección, cualquiera puede saltarse el flujo y pushear directamente a `main`.

---

## 📚 Fundamento

> [!info] Antes de empezar: proteger `main` es poner un guardia
> Hasta ahora, el flujo PR era una **buena costumbre**, pero nada impedía saltárselo. Una **regla de protección** convierte esa costumbre en **obligación**: GitHub **rechaza** los push directos a `main` y exige que todo pase por PR con revisión.

> [!abstract] Idea clave: la regla protege el escaparate
> `main` es la versión estable (el escaparate). Protegerla garantiza que **solo entra lo revisado**. Es lo que se hace en cualquier equipo serio.

> [!example] Vocabulario de esta práctica
> - **Branch protection rule:** regla que restringe qué se puede hacer en una rama.
> - **Require a pull request:** obliga a que todo cambio pase por PR.
> - **Require approvals:** exige un número mínimo de aprobaciones.

---

## 🛠️ Procedimiento

> [!example] Paso 1 — Abre las reglas de rama
> En GitHub: **Settings → Branches → "Add branch protection rule"**.

> [!example] Paso 2 — Indica la rama a proteger
> En **"Branch name pattern"**, escribe `main`.

> [!example] Paso 3 — Activa las protecciones
> Marca:
> - **"Require a pull request before merging"**
> - **"Require approvals"** → **1**
> - **"Dismiss stale pull request approvals when new commits are pushed"**
> - **"Do not allow bypassing the above settings"**
>
> Pulsa **Save**.

> [!example] Paso 4 — Compruébalo intentando saltártelo
> Desde local, intenta pushear directo a `main`:
> ```
> git switch main
> # (edita algo, git add, git commit)
> git push origin main
> ```
> Debe **fallar** con un error de protección. ✔ Funciona.

---

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Siendo admin, el push directo cuela | La regla se puede saltar | Activa **"Do not allow bypassing"**. |
> | Pones el patrón mal (`Main`, `mian`) | No protege la rama | Escribe exactamente `main`. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - La regla aparece activa en Settings → Branches.
> - `git push origin main` directo es **rechazado**.

> 2. ¿Por qué se protege `main` y no `develop`?
