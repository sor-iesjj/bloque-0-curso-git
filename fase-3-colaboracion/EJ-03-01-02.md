## EJ-03-01-02 — Marko abre su primer Pull Request

> [!info] Situación
> Lucía: *"A partir de ahora, NADIE fusiona directamente a `main`. Todo va por Pull Request. Yo reviso cada uno."* Marko crea su primer PR.

- **🎯 Objetivo real:** aprender a abrir un **Pull Request** desde una rama feature hacia `develop`.
- **🧩 Problema que resuelve:** sin PR no hay revisión, ni discusión, ni control de calidad: los cambios entran a ciegas.

---

## 📚 Fundamento

> [!info] Antes de empezar: ¿qué es un Pull Request?
> Un **Pull Request (PR)** es una **propuesta de fusión**: dices *"quiero meter los cambios de mi rama en `develop`; revisadlos antes"*. No fusiona de golpe: abre un espacio donde el equipo **lee el cambio, comenta y aprueba**. Es la herramienta central del trabajo en equipo con GitHub.

> [!abstract] Idea clave: el PR es una conversación, no un botón
> Un PR no es solo "subir": es **pedir opinión**. Por eso lleva **título** y **descripción** (qué cambia, por qué, qué queda pendiente). Cuanto mejor lo expliques, más fácil se lo pones a quien revisa.

> [!example] Vocabulario de esta práctica
> - **Pull Request (PR):** propuesta de fusión revisable.
> - **Base:** la rama a la que quieres fusionar (aquí `develop`).
> - **Compare:** la rama con tus cambios (la feature).

---

## 🛠️ Procedimiento

> [!example] Paso 1 — Crea la rama feature y trabaja
> ```
> git switch develop
> git switch -c feature/manual-ssh
> ```
> Crea `01_linux_server/configuracion_ssh.md` con contenido, y súbelo:
> ```
> git add 01_linux_server/configuracion_ssh.md
> git commit -m "EJ-03-01-02 · Manual de configuración SSH"
> git push -u origin feature/manual-ssh
> ```

> [!example] Paso 2 — Abre el Pull Request en GitHub
> Al recargar el repo aparece el banner **"Compare & pull request"**. Púlsalo.

> [!example] Paso 3 — Configura el PR
> - **Base:** `develop`   ·   **Compare:** `feature/manual-ssh`
> - **Título:** `EJ-03-01-02 · Manual de configuración SSH`
> - **Descripción:**
>   ```
>   ## Qué cambia
>   Añadido manual de configuración SSH en srv-boochan-01.
>
>   ## Por qué
>   Lucía pidió documentar SSH antes del próximo audit.
>
>   ## Pendientes
>   - [ ] Añadir sección sobre claves ed25519
>   ```

> [!example] Paso 4 — Créalo
> Pulsa **"Create pull request"**. Queda **abierto**, pendiente de revisión.

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Eliges mal Base/Compare | El PR compara ramas equivocadas | Base = destino (`develop`), Compare = tu feature. |
> | Descripción vacía | Quien revisa no sabe qué mira | Explica siempre **qué** y **por qué**. |
> | Olvidas el `push` antes del PR | GitHub no ve tu rama | Sube la rama con `push -u` primero. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - El PR existe y está **abierto** (pestaña "Pull requests").
