## EJ-03-01-04 — Marko fusiona su PR aprobado

> [!info] Situación
> Lucía ha **aprobado** el PR de Marko. Toca fusionarlo.

- **🎯 Objetivo real:** fusionar un PR desde la interfaz de GitHub, eligiendo el método adecuado, y sincronizar en local.
- **🧩 Problema que resuelve:** sin fusionar, el PR se queda abierto para siempre y el cambio nunca llega a `develop`.

---

## 📚 Fundamento

> [!info] Antes de empezar: fusionar el PR = cerrar el círculo
> Una vez aprobado, el PR se **fusiona** desde GitHub (no hace falta la terminal para esto). GitHub trae los cambios a la rama base (`develop`), cierra el PR y ofrece **borrar la rama**. Después, en tu ordenador, actualizas con `git pull`.

> [!abstract] Idea clave: tres formas de fusionar (hoy, la sencilla)
> GitHub ofrece **merge commit**, **squash** y **rebase**. Por ahora usamos **"Create a merge commit"** (conserva todo el histórico). Squash y rebase se ven en la parte N3.

> [!example] Vocabulario de esta práctica
> - **Merge pull request:** botón que fusiona el PR.
> - **Merged:** estado morado del PR una vez fusionado.
> - **Delete branch:** limpiar la rama tras fusionar.

---

## 🛠️ Procedimiento

> [!example] Paso 1 — Fusiona desde el PR
> En el PR aprobado, pulsa **"Merge pull request"** y elige **"Create a merge commit"**. Confirma.

> [!example] Paso 2 — Limpia la rama
> GitHub ofrece **"Delete branch"**: púlsalo para no dejar ramas muertas.

> [!example] Paso 3 — Sincroniza en local
> ```
> git switch develop
> git pull
> git branch -d feature/manual-ssh
> ```

---

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Fusionas sin que esté aprobado | Te saltas la revisión | Espera al "Approve" (o a que lo permita la protección de rama). |
> | No haces `git pull` después | Tu `develop` local se queda atrás | Tras fusionar en GitHub, `pull` en local. |
> | Dejas la rama sin borrar | Ramas muertas acumuladas | Usa "Delete branch" y `git branch -d`. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - El PR aparece como **"Merged"** (morado).
> - El manual SSH está en `develop`, también en tu copia local.

## ✅ Entregables y cierre

- **Entregable GitHub:** PR cerrado y fusionado; manual SSH en `develop`.
- **Entregable bóveda:** manual SSH en `develop` local.
- **Criterio de éxito:** PR "Merged" y manual SSH en `develop` local.

> [!summary] 🎓 Qué has aprendido en este ejercicio
> - A **fusionar un PR** aprobado desde GitHub y a **borrar** la rama.
> - Que existen tres métodos de fusión (hoy, el **merge commit**).
> - A **sincronizar** tu copia local con `git pull` tras la fusión.
