## EJ-03-02-01 — Marko hace un fork del repo de Lucía

> [!info] Situación
> Lucía tiene un repo público con plantillas: `lucia-boochan/plantillas-procedimientos`. Marko quiere mejorar una plantilla y proponer el cambio. Como **NO** es colaborador, hace un **fork**.

- **🎯 Objetivo real:** aprender el modelo **fork**: copiar a tu cuenta el repo de otra persona, modificarlo y proponer un PR.
- **🧩 Problema que resuelve:** sin fork, no puedes contribuir a repos donde no eres colaborador (la mayoría del código abierto).

---

## 📚 Fundamento

> [!info] Antes de empezar: colaborador vs. fork
> Hay dos formas de contribuir a un repo:
> - **Eres colaborador** → trabajas dentro del propio repo (lo de la parte N1).
> - **NO eres colaborador** → haces un **fork**: una **copia tuya** del repo en tu cuenta. Trabajas en tu copia y luego propones el cambio al original con un PR.

> [!abstract] Idea clave: el fork es tuyo, el PR viaja al original
> Tu fork es **propiedad tuya**: puedes hacer lo que quieras. Cuando quieras que tu mejora entre en el repo de Lucía, abres un PR **desde tu fork hacia el original**. Lucía decide si lo acepta.

> [!example] Vocabulario de esta práctica
> - **Fork:** copia de un repo ajeno en tu propia cuenta.
> - **Upstream:** el repo original (el de Lucía).
> - **PR desde fork:** propuesta de cambio de tu copia al original.

---

## 🛠️ Procedimiento

> [!example] Paso 1 — Haz el fork
> En GitHub, entra en el repo de Lucía (en clase: un repo del profesor) y pulsa **"Fork"** → confirma. Se crea `TU-USUARIO/plantillas-procedimientos`.

> [!example] Paso 2 — Clona tu fork
> *🔑 SSH*
> ```bash
> git clone git@github.com:TU-USUARIO/plantillas-procedimientos.git
> ```
> *🔐 HTTPS*
> ```bash
> git clone https://github.com/TU-USUARIO/plantillas-procedimientos.git
> ```
> Y entra: `cd plantillas-procedimientos`.

> [!example] Paso 3 — Crea una rama y mejora la plantilla
> ```
> git switch -c mejora/clarificar-pasos
> ```
> Edita una plantilla (por ejemplo, numerando los pasos), y súbela:
> ```
> git add .
> git commit -m "EJ-03-02-01 · Mejorada plantilla: pasos numerados explícitos"
> git push -u origin mejora/clarificar-pasos
> ```

> [!example] Paso 4 — Abre el PR hacia el original
> En **tu fork**, aparece el banner **"Compare & pull request"**. Ábrelo: el PR va de tu fork **al repo original** de Lucía, que decidirá si lo acepta.

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Editas directamente el repo de Lucía | No tienes permiso | Haz fork y trabaja en TU copia. |
> | Abres el PR desde el repo equivocado | El cambio no llega al original | El PR va **desde tu fork** hacia el original. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - Tu fork existe en `https://github.com/TU-USUARIO/plantillas-procedimientos`.
> - El PR está enviado al repo original.

> 2. ¿De quién es la copia que creas al hacer fork?
> 3. ¿Hacia dónde viaja el PR que abres desde tu fork?

## ✅ Entregables y cierre

- **Entregable GitHub:** fork creado + PR abierto contra el original.
- **Entregable bóveda:** sin cambios.
- **Criterio de éxito:** fork visible y PR enviado al original.

> [!summary] 🎓 Qué has aprendido en este ejercicio
> - El modelo **fork**: copiar un repo ajeno a tu cuenta para contribuir.
> - Que el fork es **tuyo** y el PR viaja **al original** (upstream).
> - La diferencia entre contribuir como **colaborador** o desde un **fork**.
