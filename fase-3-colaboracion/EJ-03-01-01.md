## EJ-03-01-01 — Marko da acceso de colaborador a Carlos

> [!info] Situación
> Lucía: *"A partir de ahora Carlos también va a editar tu repositorio de manuales. Dale permisos."*

- **🎯 Objetivo real:** añadir **colaboradores** en GitHub para que puedan hacer `push` directamente al repositorio.
- **🧩 Problema que resuelve:** sin permisos, otra persona solo puede proponer cambios desde fuera (fork + PR). Para trabajar en pareja con fluidez, mejor darle acceso directo.

> [!note] En clase trabajas en BINOMIO
> Aquí empieza el trabajo por parejas. "Carlos" es **tu compañero/a de binomio**: os daréis acceso mutuo a vuestros repositorios para practicar la colaboración real (PRs, revisiones, ramas).

---

## 📚 Fundamento

> [!info] Antes de empezar: ¿quién puede tocar un repo?
> Un repositorio en GitHub tiene un **dueño (owner)** y, opcionalmente, **colaboradores**. El owner puede hacerlo todo; un colaborador con permiso **Write** puede clonar, crear ramas y hacer `push`. Sin ser colaborador, solo puedes **leer** (o proponer cambios desde un fork).

> [!abstract] Idea clave: acceso directo vs. propuesta externa
> - **Colaborador (Write):** trabajáis "dentro de casa", cada uno en su rama. Es lo cómodo para un binomio.
> - **Sin acceso:** propones cambios "desde fuera" con fork + Pull Request (lo verás en la parte N2).

> [!example] Vocabulario de esta práctica
> - **Owner:** dueño del repositorio.
> - **Colaborador:** persona con permiso para empujar cambios.
> - **Permiso Write:** puede hacer `push`; **Read** solo leer.

---

## 🛠️ Procedimiento

> [!example] Paso 1 — Abre los ajustes de colaboradores
> En GitHub: repo **`manuales-boochan` → Settings → Collaborators**. *(Solo el **owner** ve esta opción.)*

> [!example] Paso 2 — Añade a tu compañero/a de binomio
> Pulsa **"Add people"** y escribe su **username** de GitHub. Asigna permiso **"Write"**.

> [!example] Paso 3 — El compañero acepta la invitación
> Le llega un email (o una notificación en GitHub). Debe **aceptar** para quedar dentro.

> [!example] Paso 4 — El compañero prueba el acceso
> Clona el repo, crea una rama y hace un commit pequeño con `push`:
> ```
> git clone git@github.com:TU-USUARIO/manuales-boochan.git
> git switch -c prueba/acceso-compañero
> # (edita algo, git add, git commit)
> git push -u origin prueba/acceso-compañero
> ```

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | El compañero no ve "Settings" | No es el owner | Solo el dueño gestiona colaboradores. |
> | El compañero no acepta la invitación | Sigue sin acceso | Debe aceptar el email/notificación antes de probar. |
> | Le das permiso "Read" en vez de "Write" | No puede hacer push | Revisa el permiso: debe ser **Write**. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - El compañero aparece en **Settings → Collaborators**.
> - El compañero hace un commit y `push` con éxito.
