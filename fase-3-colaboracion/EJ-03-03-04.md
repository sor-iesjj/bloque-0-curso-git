## EJ-03-03-04 — Marko usa Draft Pull Requests

> [!abstract] Ficha de la práctica
> ### 📌 `F3.3.4` — Marko usa Draft Pull Requests
> - **Fase 3** (Colaboración) · **Nivel 3** (Sobresaliente)
> - **🎬 Playlist:** `Curso Git — Fase 3`
> - **📹 Nombre del vídeo:** `F3.3.4 · Marko usa Draft Pull Requests`

> [!info] Situación
> Marko quiere abrir el PR **pronto** para discutirlo con el equipo, pero **no** está listo para fusionar todavía. Usa un **Draft PR** (borrador).

- **🎯 Objetivo real:** conocer los **Draft PR** como "trabajo en progreso visible pero **no** fusionable".
- **🧩 Problema que resuelve:** si abres un PR normal a medias, alguien podría fusionarlo antes de tiempo.

---

## 📚 Fundamento

> [!info] Antes de empezar: enseñar sin arriesgar
> Un **Draft PR** es un PR marcado como **borrador**: se ve, se comenta y se discute, pero GitHub **bloquea el botón de fusionar**. Sirve para pedir **feedback temprano** sin miedo a que se fusione algo incompleto.

> [!abstract] Idea clave: dos estados del PR
> - **Draft (borrador):** en construcción, NO fusionable.
> - **Ready for review:** terminado, ya se puede revisar y fusionar.
> Tú decides cuándo pasa de uno a otro.

> [!example] Vocabulario de esta práctica
> - **Draft PR:** PR en borrador, no fusionable.
> - **Ready for review:** botón que lo marca como listo.

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Abres PR normal a medias | Riesgo de fusión prematura | Ábrelo como **Draft** hasta que esté listo. |
> | Olvidas pasarlo a "Ready" | Nadie lo revisa | Marca "Ready for review" al terminar. |
