> [!info] Situación
> Lucía: *"Quiero que la versión `v1.1.0` aparezca como Release oficial con notas, para que cualquiera pueda descargar el repositorio en ese estado."*

- **🎯 Objetivo real:** convertir un **tag** en una **Release** con notas y archivos descargables.
- **🧩 Problema que resuelve:** un tag es algo técnico; una Release es pública, con notas humanas y descargas.

---

## 📚 Fundamento

> [!info] Antes de empezar: tag vs Release
> Un **tag** es un marcador interno de Git. Una **Release** de GitHub es la versión "de cara al público": coge un tag y le añade **título**, **notas** (qué hay de nuevo) y **descargas** (GitHub adjunta el ZIP/TAR del repo en ese punto). Un tag es para técnicos; una Release, para cualquiera.

> [!abstract] Idea clave: las notas son para personas
> Las notas de una Release las lee gente que quizá no conoce el detalle técnico. Escribe **novedades** en lenguaje claro: qué se ha añadido, qué ha cambiado, qué viene después.

> [!example] Vocabulario de esta práctica
> - **Release:** versión publicada con notas y descargas.
> - **Pre-release:** versión no definitiva (se marca aparte).
> - **Assets:** los archivos que GitHub adjunta (ZIP/TAR).
