## EJ-04-02-05 — Marko automatiza con un hook de validación de mensajes

> [!info] Situación
> Marko quiere asegurarse de que **TODOS** sus commits llevan un mensaje que empieza por `EJ-FF-NN-OO`. Si no, que el commit **falle** automáticamente.

- **🎯 Objetivo real:** configurar un **hook** `commit-msg` que valide el mensaje del commit.
- **🧩 Problema que resuelve:** sin hook, Marko se olvida del prefijo y el profesor no puede verificar los entregables.

---

## 📚 Fundamento

> [!info] Antes de empezar: un hook es un "guardián automático"
> Un **hook** de Git es un pequeño script que se ejecuta **solo**, en un momento concreto. El hook **`commit-msg`** salta justo cuando vas a commitear: revisa el mensaje y, si no cumple, **cancela el commit**. Es un guardián que no se olvida nunca.

> [!warning] Los hooks son LOCALES
> Los hooks viven en `.git/hooks/` y **no se suben a GitHub**. Cada persona los instala en su equipo (o se usan herramientas como `husky` para compartirlos). Por eso los **documentamos** en la bóveda.

> [!example] Vocabulario de esta práctica
> - **Hook:** script que Git ejecuta automáticamente en un evento.
> - **`commit-msg`:** hook que valida el mensaje del commit.
> - **`exit 1`:** el script termina con error → Git cancela el commit.

---

## 🛠️ Procedimiento
Dentro de `Manuales/`.

> [!example] Paso 1 — Entra en la carpeta de hooks
> *🐧 Git Bash / Linux*
> ```bash
> cd .git/hooks
> ```
> *🪟 PowerShell*
> ```powershell
> cd .git\hooks
> ```

> [!example] Paso 2 — Crea el archivo `commit-msg` (sin extensión)
> *🐧 Git Bash / Linux*
> ```bash
> touch commit-msg
> ```
> *🪟 PowerShell*
> ```powershell
> New-Item commit-msg -ItemType File
> ```

> [!example] Paso 3 — Escribe la validación
> Edita `commit-msg` con este contenido:
> ```sh
> #!/bin/sh
> # Valida que el mensaje empieza por EJ-NN-NN-NN o Merge/Revert/Initial
> msg=$(cat "$1")
> if echo "$msg" | grep -qE "^(EJ-[0-9]{2}-[0-9]{2}-[0-9]{2}|Merge|Revert|Initial)"; then
>   exit 0
> else
>   echo "ERROR: el mensaje debe empezar por EJ-FF-NN-OO o Merge/Revert/Initial."
>   exit 1
> fi
> ```

> [!example] Paso 4 — Pruébalo
> - Intenta commitear con mensaje `"prueba"` → **falla**.
> - Intenta con `"EJ-04-02-05 · prueba"` → **pasa**.

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Le pones extensión (`commit-msg.txt`) | Git no lo ejecuta | El archivo se llama **`commit-msg`**, sin extensión. |
> | Esperas que el hook viaje a GitHub | Los hooks son locales | Documenta el hook; instálalo en cada equipo. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - Un commit con mensaje **sin** formato es **rechazado**.
> - Un commit con el formato correcto **pasa**.

## ✅ Entregables y cierre

- **Entregable GitHub:** ninguno (los hooks no se versionan por defecto).
- **Entregable bóveda:** documenta el hook en `Manuales/00_infraestructura/configuracion_git.md`.
- **Criterio de éxito:** el hook rechaza mensajes sin formato y acepta los correctos.

> [!summary] 🎓 Qué has aprendido en este ejercicio
> - Qué es un **hook** y cómo `commit-msg` valida el mensaje automáticamente.
> - A escribir una validación que **cancela** el commit (`exit 1`).
> - Que los hooks son **locales** y hay que documentarlos/distribuirlos.
