## EJ-02-01-03 — Marko crea una rama feature para un manual nuevo

> [!info] Situación
> Lucía: *"Empieza el manual de Samba AD DC, pero no lo subas a `main` hasta que esté completo. Trabájalo en una rama aparte."* Marko aplica el patrón "una rama por manual".

- **🎯 Objetivo real:** practicar el flujo profesional **"feature branch"**: una rama por cada trabajo aislado, que se fusiona cuando está listo.
- **🧩 Problema que resuelve:** sin ramas *feature*, el trabajo a medias se mezcla en `main` y la rama principal pierde su papel de "estado estable".

---

## 📚 Fundamento

> [!info] Antes de empezar: rama "experimento" vs rama "feature"
> Son el mismo mecanismo (una rama), pero con distinta intención:
> - Una **rama de experimento** es para "probar a ver": puede acabar en la basura.
> - Una **rama feature** es para **construir algo que sí va a entrar** (un manual, una función), pero de forma aislada hasta que esté terminado.
> Por convención, se nombran `feature/<nombre-corto>`.

> [!abstract] Idea clave: trabajo aislado = trabajo seguro
> Mientras el manual de Samba está a medias, `main` no debe verlo. La rama feature te deja avanzar tranquilo: aunque dejes cosas incompletas, la versión oficial sigue limpia.

> [!example] Vocabulario de esta práctica
> - **Feature branch:** rama para construir algo concreto de forma aislada.
> - **Convención `feature/…`:** forma estándar de nombrar estas ramas.

---

## 🛠️ Procedimiento
Trabaja dentro de `Manuales/`.

> [!example] Paso 1 — Crea la rama feature
> ```
> git switch -c feature/manual-samba
> ```

> [!example] Paso 2 — Crea el fichero del manual
> Por terminal **o** en Obsidian (*New note*):
>
> *🐧 Git Bash / Linux*
> ```bash
> touch 02_active_directory/samba_ad_dc.md
> ```
> *🪟 PowerShell*
> ```powershell
> New-Item 02_active_directory\samba_ad_dc.md -ItemType File
> ```

> [!example] Paso 3 — Escribe el esqueleto del manual
> Edita `02_active_directory/samba_ad_dc.md`:
> ```
> # Samba AD DC en srv-boochan-01
>
> ## Objetivo
> Configurar srv-boochan-01 como controlador de dominio Active Directory
> compatible con clientes Windows usando Samba 4.
>
> ## Requisitos previos
> - Ubuntu Server 24.04 LTS instalado (ver instalacion_ubuntu.md)
> - Acceso SSH funcionando
> - Hostname y FQDN configurados
>
> ## Pasos (PENDIENTE de completar)
> 1. Instalar paquetes
> 2. Provisionar dominio
> 3. Configurar Kerberos
> 4. Verificar
> ```

> [!example] Paso 4 — Guárdalo con un commit (en la rama)
> ```
> git add 02_active_directory/samba_ad_dc.md
> git commit -m "EJ-02-01-03 · Esqueleto manual Samba AD DC"
> ```

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Empiezas el manual en `main` | Metes trabajo a medias en la versión oficial | Crea la rama feature **antes** de tocar nada. |
> | Nombras la rama sin convención | Difícil de reconocer | Usa `feature/<nombre-corto>`. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - La rama `feature/manual-samba` existe (`git branch`).
> - El manual está creado con su contenido base, dentro de la rama.
