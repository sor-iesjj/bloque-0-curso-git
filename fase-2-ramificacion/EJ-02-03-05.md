## EJ-02-03-05 — Marko usa `bisect` para encontrar el commit que rompió todo

> [!info] Situación
> Hace 20 commits, los enlaces internos del manual de Samba dejaron de funcionar. Marko no sabe en qué commit se rompieron. Tiene que encontrarlo.

- **🎯 Objetivo real:** usar `git bisect` (búsqueda binaria) para localizar el commit problemático rápidamente.
- **🧩 Problema que resuelve:** sin bisect, Marko probaría commit por commit; bisect lo encuentra en muy pocos pasos.

---

## 📚 Fundamento

> [!info] Antes de empezar: buscar por la mitad
> `git bisect` es como buscar una palabra en el diccionario: no vas página a página, vas **por la mitad**. Le dices a Git un commit **bueno** (antiguo, funcionaba) y uno **malo** (actual, roto). Git salta al **punto medio**, tú pruebas, y según funcione o no, descarta **la mitad** de los commits. En pocos saltos, encuentra el culpable.

> [!abstract] Idea clave: tú juzgas, Git decide a dónde ir
> Bisect es **semiautomático**: en cada paso Git te lleva a un commit y tú solo dices `good` o `bad`. Git se encarga de calcular a dónde saltar.

> [!example] Vocabulario de esta práctica
> - **`git bisect start`:** empieza la búsqueda.
> - **`git bisect good` / `bad`:** marcas si ese commit funciona o no.
> - **`git bisect reset`:** termina y te devuelve a donde estabas.

---

## 🛠️ Procedimiento

> [!example] Paso 1 — Inicia la búsqueda
> ```
> git bisect start
> ```

> [!example] Paso 2 — Marca el estado actual como MALO
> ```
> git bisect bad
> ```

> [!example] Paso 3 — Marca un punto antiguo conocido como BUENO
> ```
> git bisect good v1.0.0
> ```
> Git salta a un commit intermedio.

> [!example] Paso 4 — Prueba ese commit
> Abre el manual y comprueba si los enlaces funcionan.

> [!example] Paso 5 — Dile a Git el resultado
> ```
> git bisect good   # si funciona
> git bisect bad    # si NO funciona
> ```
> Repite los pasos 4-5. Git irá acotando hasta decir: **"first bad commit is <hash>"**.

> [!example] Paso 6 — Cierra el bisect
> ```
> git bisect reset
> ```

---

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Marcas bien/mal al revés | Bisect apunta al commit equivocado | Ten claro: bueno = funciona, malo = roto. |
> | Terminas sin `git bisect reset` | Te quedas "atrapado" en un commit antiguo | Cierra siempre con `git bisect reset`. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - Marko identifica el **commit culpable**.
> - El bisect queda cerrado con `reset`.
