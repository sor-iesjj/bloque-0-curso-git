## EJ-02-03-04 — Marko revierte un commit ya pusheado (`git revert`)

> [!abstract] Ficha de la práctica
> ### 📌 `F2.3.4` — Marko revierte un commit ya pusheado (`git revert`)
> - **Fase 2** (Ramificación) · **Nivel 3** (Sobresaliente)
> - **🎬 Playlist:** `Curso Git — Fase 2`
> - **📹 Nombre del vídeo:** `F2.3.4 · Marko revierte un commit ya pusheado (git revert)`

> [!info] Situación
> Marko fusionó hace 3 días un cambio que rompió la guía de Samba. El cambio ya está en GitHub y **otros lo tienen**. No puede borrarlo. Necesita un commit que "deshaga" el daño **manteniendo el histórico**.

- **🎯 Objetivo real:** usar `git revert` para crear un commit que **invierte** uno anterior, sin borrar histórico.
- **🧩 Problema que resuelve:** si Marko usara `git reset --hard` + `push --force` en una rama compartida, rompería el repo de sus compañeros.

---

## 📚 Fundamento

> [!info] Antes de empezar: deshacer sin borrar
> Hay dos formas de "deshacer" un commit:
> - **Borrarlo del histórico** (`reset`) → peligroso en ramas compartidas.
> - **Añadir un commit que hace lo contrario** (`revert`) → seguro, porque no toca el pasado, solo suma un paso nuevo que anula el daño.
> En algo ya compartido, **siempre `revert`**.

> [!abstract] Idea clave: el histórico es una cuenta bancaria
> No borras un movimiento antiguo: haces uno **nuevo** que lo compensa. Así todos ven qué pasó y cómo se corrigió. `git revert` es exactamente eso.

> [!example] Vocabulario de esta práctica
> - **`git revert <hash>`:** crea un commit que invierte el commit indicado.
> - **`reset` vs `revert`:** reset borra historia (privado); revert la conserva (compartido).
> - **Revertir un merge:** `git revert -m 1 <hash>`.

## 🚩 Errores y verificación

> [!danger] Nunca uses `reset --hard` + `push --force` en algo compartido
> Reescribir el pasado de una rama que otros usan les rompe el repositorio. En lo compartido, la herramienta correcta es `git revert`.

> [!warning] Si el commit malo era un merge
> Un merge tiene dos "padres"; hay que decirle a Git cuál conservar:
> ```
> git revert -m 1 <hash>
> ```

> [!success] ✅ Verificación: ¿está bien hecho?
> - `git log` muestra **ambos**: el commit original y el "Revert ...".
> - El estado de los archivos vuelve a ser el correcto.
