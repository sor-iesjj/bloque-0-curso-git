## EJ-02-02-04 — Marko se enfrenta a su primer conflicto de merge

> [!info] Situación
> Marko y Carlos han editado el mismo archivo (`README.md`) en paralelo, cada uno en su rama, tocando la **misma línea**. Cuando Marko intenta fusionar, Git se detiene: hay **conflicto**.

- **🎯 Objetivo real:** identificar las marcas de conflicto, decidir qué versión se queda y resolverlo.
- **🧩 Problema que resuelve:** sin saber resolver conflictos, Marko queda bloqueado al primer merge problemático.

---

## 📚 Fundamento

> [!info] Antes de empezar: ¿por qué hay conflictos?
> Git fusiona **solo** cuando puede decidir sin dudar. Pero si **dos ramas cambian la misma línea** de forma distinta, Git no sabe cuál vale: se **detiene** y te pide **a ti** que decidas. No es un error: es Git siendo prudente.

> [!abstract] Idea clave: las marcas de conflicto
> Git escribe en el archivo tres marcas que separan las dos versiones:
> ```
> <<<<<<< HEAD
> (lo que hay en TU rama actual)
> =======
> (lo que trae la otra rama)
> >>>>>>> nombre-de-la-otra-rama
> ```
> Resolver = **editar a mano** para dejar la versión final y **borrar las tres marcas**.

> [!example] Vocabulario de esta práctica
> - **Conflicto:** cuando dos ramas cambian la misma línea distinto.
> - **HEAD:** la rama en la que estás antes del merge.
> - **`git merge --abort`:** cancela el merge y vuelve al estado anterior (si te lías).

---

## 🛠️ Procedimiento
Vamos a **provocar** un conflicto a propósito para aprender a resolverlo.

> [!example] Paso 1 — Crea una rama y cambia la línea 2 del README
> ```
> git switch develop
> git switch -c feature/marko-readme
> ```
> Edita la línea 2 del `README.md`: `Mantenido por Marko con cariño.` y:
> ```
> git add README.md
> git commit -m "EJ-02-02-04a · Línea Marko en README"
> ```

> [!example] Paso 2 — Simula el cambio "de Carlos" en `develop`
> ```
> git switch develop
> ```
> Edita la **MISMA** línea 2: `Mantenido por Carlos con eficacia.` y:
> ```
> git add README.md
> git commit -m "EJ-02-02-04b · Línea Carlos en README"
> ```

> [!example] Paso 3 — Fusiona y provoca el conflicto
> ```
> git merge feature/marko-readme
> ```
> Git anuncia un **conflicto** y se detiene.

> [!example] Paso 4 — Abre el README y mira las marcas
> Verás:
> ```
> <<<<<<< HEAD
> Mantenido por Carlos con eficacia.
> =======
> Mantenido por Marko con cariño.
> >>>>>>> feature/marko-readme
> ```

> [!example] Paso 5 — Decide la versión final y borra las marcas
> Edita a mano para dejar, por ejemplo:
> ```
> Mantenido por Marko y Carlos en equipo.
> ```
> Asegúrate de **borrar** las líneas `<<<<<<<`, `=======` y `>>>>>>>`.

> [!example] Paso 6 — Marca el conflicto como resuelto y cierra el merge
> ```
> git add README.md
> git commit -m "EJ-02-02-04 · Resuelto conflicto README (combinado Marko+Carlos)"
> git branch -d feature/marko-readme
> ```

---

## 🚩 Errores y verificación

> [!danger] No dejes marcas de conflicto en el archivo
> Si te dejas un `<<<<<<<` o un `=======`, ese texto queda en el manual y rompe el documento. Revisa que **no quede ninguna** antes del commit.

> [!warning] Si te agobias, puedes cancelar
> ```
> git merge --abort
> ```
> Deja todo como estaba antes del merge, para volver a intentarlo con calma.

> [!success] ✅ Verificación: ¿está bien hecho?
> - El README **no** tiene marcas `<<<`, `===` ni `>>>`.
> - `git log --oneline --graph` muestra el merge resuelto.

> [!question] Comprueba que lo has entendido
> Responde en tu bitácora:
> 1. ¿Por qué se produce un conflicto de merge?
> 2. ¿Qué representa cada parte entre `<<<<<<< HEAD`, `=======` y `>>>>>>>`?
> 3. ¿Qué comando cancela un merge si te lías?

## ✅ Entregables y cierre

- **Entregable GitHub:** push tras el merge resuelto.
- **Entregable bóveda:** README final con la frase combinada.
- **Criterio de éxito:** README sin marcas y merge visible en el grafo.

> [!summary] 🎓 Qué has aprendido en este ejercicio
> - Por qué Git se **detiene** ante un conflicto (dos cambios en la misma línea).
> - A **leer las marcas** de conflicto y a resolverlo editando a mano.
> - Que puedes **cancelar** un merge con `git merge --abort`.
